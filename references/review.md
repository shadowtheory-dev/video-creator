# Review: how the user likes to see work

- **Side by side.** Options are built as separate pages or tabs and shown live in the browser pane, not described: option A and B of a re-time as two tabs of the real film; cuts as tabs in the track editor with each cut's film window; a phone cut next to the master. Name tabs by what differs ("Current cut", "Re-edit C").
- **Live assets.** Drawn assets (SVG, iso) are reviewed live in the browser pane through a launch config that serves the folder, with zoom, pan and preset views. PNG crops are for your own checks only, or for canvas-only effects.
- **Track editor.** For music: the editor open in the pane on the cut's tab, the film window muted and following the transport, the transport visible.
- **Every render has a Discord copy** (under 10 MB, `finish.sh <mp4> discord`), drafts included. Send it as a file card; reveal the folder in Finder (`reveal_path`) instead of printing paths, which the user can't click.
- **Drafts while scoping.** Fast renders (30 fps, no motion blur) for every scoping round; 60 fps finals only after approval.
- **Before/after pages.** For a big round, a page with the old frame against the new frame for each note, the user's words beside each, the new film embedded, and the waveforms when sound changed. Publish privately; keep the source in the film's `review/`.
- **Storyboard pages** for story rounds: panels, captions, moves, sound, timing strip; low-fi.
- **Stills.** Contact sheets per section (`sheet.sh`) for your own checks and for reports.
- **Reports** say what changed, what's open, and the decisions the user owns, in plain text. No question cards, no next-step buttons. Say "strongest so far", never "X it is", during exploration.
